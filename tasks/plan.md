# Технический план: `app-shell` для нативного SYNCRA

## Обзор

Создать отдельный SwiftUI-проект в `ios/SYNCRA/`, не изменяя текущую PWA. Нативное приложение сначала доставляет узнаваемый каркас SYNCRA: чёрный фон, зелёный акцент, нижняя навигация и четыре экрана-заглушки. Это даёт устанавливаемую основу для следующих модулей тренировок и дневного трекинга.

## Решения по архитектуре

- **SwiftUI вместо web view.** Каждый экран — нативный `View`; PWA не встраивается в приложение.
- **Локальные данные.** На старте сохраняется только выбранная вкладка через `AppStorage`; SwiftData подключается вместе с первой моделью тренировки, а не заранее.
- **Системные символы.** SF Symbols обеспечивают нативный внешний вид и не добавляют зависимости.
- **Сохранение PWA.** Веб-приложение остаётся в корне репозитория, а iOS-проект изолирован в `ios/SYNCRA/`.

## Граф зависимостей

```text
Xcode project
    └── DesignSystem
          └── AppShellView + tab state
                └── Today / Streak / Progress / Profile placeholder screens
                      └── later: workout-session and daily-tracking
```

## Последовательность реализации

1. Создать валидный Xcode-проект с минимальным target iOS 17 и настройкой bundle identifier.
2. Добавить `DesignSystem`: цвета, карточки, типографику и reusable таб-элемент.
3. Собрать `AppShellView` с четырьмя вкладками и сохранением выбранной вкладки.
4. Добавить по одному содержательному пустому состоянию на каждый экран; `Сегодня` станет точкой подключения тренировок.
5. Скомпилировать проект в симуляторе и открыть его в Xcode для установки на iPhone.

## Контрольные точки

### После фундамента

- Проект открывается в Xcode без сторонних зависимостей.
- Сборка симулятора проходит после установки Xcode.

### После интерфейсного каркаса

- Нижняя навигация переключает четыре русскоязычных раздела.
- Стиль совпадает с чёрно-зелёной визуальной системой SYNCRA.
- Выбранная вкладка переживает перезапуск приложения.

## Риски и меры

| Риск | Влияние | Мера |
| --- | --- | --- |
| На Mac нет Xcode | Нельзя собрать и поставить на iPhone | Создать исходники и Xcode-проект; перед сборкой установить Xcode из App Store. |
| Слишком раннее добавление SwiftData | Необоснованная схема до моделей тренировок | Подключать SwiftData в `workout-session`, когда модель согласована. |
| Расхождение PWA и iOS-версии | Дублирование поведения | Не удалять PWA; переносить функции нативно модуль за модулем. |

## Открытые вопросы

- Нужна ли миграция уже записанных PWA-данных в нативную версию? Пока нет: это отдельный импорт из резервной копии.
- HealthKit остаётся отдельным модулем и потребует отдельного разрешения пользователя.
